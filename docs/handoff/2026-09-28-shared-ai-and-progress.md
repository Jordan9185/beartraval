# 兩個帳號共用 Mac AI，移除主畫面進度橫條

## 使用者要求與本次變更

- 頂部常駐 AI 進度橫條占用畫面，已從 RootView 移除。進度改從「旅程」或「今天」的「更多 → AI 進度」開啟，背景查詢與完成後更新清單持續運作。
- 指定的兩個既有帳號都可使用同一部 Mac 的 GPT 訂閱工作程式。雲端已核對目前有兩個帳號，以使用者 UUID 設定明確允許名單，未將姓名或 UUID 寫入公開設定。
- 新設定 `PERSONAL_AI_ALLOWED_USER_IDS` 取代單一 owner 限制；只有未設定新名單時相容 `PERSONAL_AI_OWNER_ID`。空白或格式錯誤的名單拒絕所有帳號，不回退放行。
- 五個 AI 排隊入口均檢查名單；Mac 按可領取工作建立時間選帳號，沿用原子領取、租約與過期工作處理。完成時由資料庫決定帳號歸屬，續租／延後也只處理名單內工作。
- 手機狀態查詢仍只回本人工作及結果；排隊序號改成「我的第 N 筆」，不把個人序號誤稱為整部 Mac 的順序。共用處理能力不公開彼此私人內容。
- 不需要新 migration，不改正式行程，也不新增付費 API fallback。Mac 既有程式可使用新 Gateway，無須搬移登入或重設憑證。

## 驗證與部署

- Swift 套件執行摘要 180 項，13 項因整合環境／外部資料未提供而略過，其餘通過；沒有將略過項目算成實測。
- 個人工作程式 17 項測試通過。新增真 Gateway 搭配記憶體資料庫測試：雙帳號排隊、第三帳號拒絕、工作憑證、領取順序、第二帳號回寫、錯誤租約拒絕、本人狀態隔離。
- 六個相關 Edge Functions 的 Deno 檢查通過；已部署 `personal-ai`、`parse-import`、`ask-trip`、`extract-products`、`organize-inbox`、`discover-places`，並設定雙帳號允許名單。
- 雲端為兩個帳號各建立一筆無行程關聯的合成商品辨識工作，既有 Mac 工作程式都成功領取並以 `codex/gpt-5.6-luna` 完成，回寫狀態均為 `extracted`。這驗證雙帳號雲端佇列到真 GPT 的往返，不等於已驗收全部手機 AI 入口；測試工作完成後按本次識別碼清除。
- 真機 Release build 成功，同一份 App 已安裝到 Jordan 與 BeaR 的 iPhone 15 Pro。兩支手機在啟動檢查時均回覆 `Locked`，因此目前記為「已安裝／啟動及畫面驗收待解鎖」，不記為已啟動或已驗收。
- 本機測試及 build 記錄在 gitignore 的 `build/qa/shared-ai-*`、`build/qa/packing-ai-swift.log`。本機 Homebrew Node 缺少相依函式庫，驗證改用既有 nvm Node 22.22.2，未改系統安裝。

## 行李清單規劃

- 已新增[行李清單提案](../spec/packing-checklist-proposal.md)，目前是草稿，尚未採用或開發。
- 建議第一版為每趟旅程的個人清單、共同物品分工、基本範本、勾選與離線保存；第二階段再加 AI 補充建議、提醒及購物連動。
- 個人／共同的使用方式尚待確認。這次 AI 修正與安裝不代表行李功能也已實作。

## 後續驗收

- 手機解鎖後啟動新版；確認頂部不再有常駐 AI 橫條，且兩個入口的「更多 → AI 進度」可正常開啟與關閉。
- 兩位使用者各從手機送一份旅行內容，確認自身工作與結果可見，對方私人紀錄不可見。
- Mac 仍須保持開機連網；睡眠、登入失效或額度不足時工作等待，不改用付費 API。
