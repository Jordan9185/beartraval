# 真實截圖辨識第二批交接

日期：2026-09-27。接續 [第一批](2026-09-27-ai-first-implementation.md)；原圖補齊後優先處理 AJ-0 辨識基線與 AJ-1 收件品質，不代表完整主線已驗收。

## 實際修正

- 使用者提供 8 個檔案，7 張不同內容；無垢屋兩份位元組相同。直接呼叫 App OCR／縮圖程式比較原圖、1024、2048，原始觀測與修正後觀測分開保留在忽略的 `build/qa/recognition-20260927/`。
- 專用韓／日文 OCR 只補該語系，不再以跨語系信心分數覆蓋長中文句。LOE 的中文價格句及問答開頭不再被錯誤韓文取代；無垢屋韓文招牌仍讀得到。這不代表所有 OCR 字形都已正確。
- 搜尋名稱排除回覆欄、串文、作者、瀏覽數及部分圖示數字；沒有合理候選不再回退到已被判定不適合的搜尋列。
- 收件圖片優先 2048 px，超過 2 MB 才依序退到 1536／1024；不覆蓋原始附件。7 張評測的 2048 JPEG 為 229,631～336,378 bytes，均在服務限制內。
- 整理提示詞明定貼文／留言分界、巢狀圖平台標籤、料理與店名的差別。刪除原先未經原圖核實的特定墨鏡店名示例，不用提示詞把模糊招牌帶向預設答案。
- 驗證器排除明顯截圖介面項目，相同圖片相同項目去重，不跨不同來源合併同名店。來源只接受模型實際看得到的前十張圖與截斷文字。
- 新增本機真模型評測入口，保留原始／驗證後結果、實際模型、時間與 token；沒有金鑰時失敗退出，不生成假結果。

## 驗證狀態

- Swift：157 項實際通過、13 項略過（含需要明確指定私有素材的評測）；摘要 170 項。
- 真實 OCR 評測另外執行：7 張 × 3 尺寸，共 21 筆觀測，修正前後分開保存；不是 21 筆正確辨識。
- inbox-organize：型別檢查與 18 項規則測試通過；不是實際模型準確率。
- 前版 [iOS CI 36288397248](https://github.com/Jordan9185/beartraval/actions/runs/36288397248) 的未登入收件測試失敗。本機以相同 `CODE_SIGNING_ALLOWED=NO` 重現保存頁顯示儲存空間不可用，原因是 App Group entitlement 缺失。CI 改模擬器 ad-hoc 簽章，保留原本成功保存的斷言，失敗時補輸出畫面結構以利定位。
- 修正後於獨立 iPhone 17 Pro／iOS 26.5 模擬器重跑同一收件 UI 測試，1 項通過且整體 `TEST SUCCEEDED`；使用明確的 ad-hoc 簽章與空 development team，不依賴個人憑證。新版遠端 iOS CI 需推送後確認。

## 未完成與部署邊界

- 本機 `ANTHROPIC_API_KEY` 未設定，真模型入口已實際執行並回報「尚未呼叫模型」。因此尚無模型準確率、模型延遲、費用或人工更正次數。執行方式與逐張標準見 [評測說明](../../ai/inbox-organize/eval/README.md)。
- OCR 仍無法可靠處理韓文混在中文句內的回覆、模糊小字、頭像品牌與餐盤殘字；搜尋建議仍可能不是店名。不可將啟發式搜尋名稱當作已確認地點。
- 未部署 migration 33 或 Edge Functions；提示詞／驗證器只有原始碼修改，雲端服務尚未更新。真機 Release、本機收件到雲端歸檔及使用者確認排入流程未驗收。
- AJ-2～AJ-4 與稽核 L01／L02／L05～L15 仍需依計畫完成。下一步是可用環境中的真模型逐項核對，以及整理結果的更正／重試與直接排程持久關聯。
