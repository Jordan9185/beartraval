# 收藏移除與卡片操作按鈕

## 使用者問題與修正

- 個人收藏原本只提供左滑「撤銷」，共同收藏也只有左滑移除，不容易發現。改成卡片直接顯示「移除收藏」；共同收藏詳情亦有同一個入口。
- 個人想買與待確認項目使用相同元件，分別顯示「移除想買」「移除候選」。移除個人項目沿用 `update_inbox_item(archived: false)`，保留原始分享，透過人工更正標記避免重新出現在待確認候選，可從收件匣再加入。
- 共同收藏沿用 `dismiss_saved`，只有可編輯旅程的成員看得到移除入口；後端仍驗證權限。確認訊息說明旅伴會看到變更，已排入的站點保留，不連帶刪除正式行程。
- 確認前可取消，送出時顯示「移除中…」並防止重複送出。成功才更新清單；失敗保留卡片、錯誤原因與重試入口。
- 卡片下方的確認地點、更正、加入旅伴清單、想去、排進旅程等改成帶圖示及邊框的按鈕。最少 44 點高度設在按鈕標籤內，整塊邊框區域都能命中；當地地圖按鈕亦調整，避免只有文字可點。

## 驗證與交付

- Swift 套件 180 項／47 suites 通過（含既有需整合環境而略過的測試）。
- DB 全套含並發測試通過；新增個人移除／原始來源保留／過期版本拒絕／重新加入，以及共同收藏移除後所有正式站點欄位與當日版本不變的驗證。
- 六項 UI 測試通過：原有卡片動作隔離、地圖按鈕邊緣可點、個人移除範圍及取消、共同移除取消／確認、失敗保留項目後重試、Viewer 無共同移除入口。使用正式卡片與移除元件；送出成功／失敗採測試回呼，持久化與權限另由上述 DB 測試驗證。
- 首輪測試發現系統 confirmationDialog 未顯示取消按鈕，改用有明確取消及確認按鈕的 alert 後，六項全部通過。最終結果：`build/qa/collection-removal-verified.xcresult`，已匯出並目視檢查收藏卡片按鈕截圖。
- Release 編譯成功，已安裝並啟動 Jordan 的 iPhone 15 Pro。手機上的真實收藏資料操作待使用者驗收；沒有代替使用者刪除既有收藏。
- 沒有後端契約或雲端資料異動，無須部署；這些操作不需要 AI。
