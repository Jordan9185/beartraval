# 第一版線框稿檢視記錄

日期：2026-09-28。依據：[新版需求草案 v0.20](../spec/rebuild-v1-spec-draft.md)。

【已確認規格】使用者授權先畫線框草稿；本次不開發 App、不部署、不操作正式資料。R1–R5 仍為可調整的例外建議，不將畫稿視為默認採用。

## 交付

【建議】可點選線框共 19 個畫面：旅程／AI 助理、收集、文字匯入、草稿核對、安排提案、修改提案、今天、站點詳情／探索、計程車卡、收藏、購買清單、商品數量、必備用品、旅伴、旅程列表、封存、地圖佔位、無旅程、共同修改衝突。

【建議】檢視順序：首頁 → AI 建議 → 勾選確認 → Today → 餐廳站點 → 附近探索／計程車卡；再查看購買與用品的分離、共同代勾及封存查閱。

【已確認規格】這是畫面與流程示意，並非可交付 App。沒有真 AI 搜尋、真實店家地址、真實活動、地圖資料、邀請連結或後端寫入；所有旅行內容均為示意。灰階方框用於確認資訊層級，不代表最終視覺樣式。

## 本輪檢查

- 19 個畫面均可切換並顯示對應標題。
- 檢查提案確認到 Today、站點到雙語計程車卡、修改商品數量、共同物品代勾的可見結果。
- 檢查封存後移出主要列表、查閱後仍保留封存狀態。
- 在 360 像素瀏覽器寬度檢查，畫稿根元素可用寬度 313 像素，內容寬度同為 313，未產生水平溢出；計程車卡已視覺檢查。
- 提供正常、AI 等待、查詢失敗、離線與共同修改衝突的切換，供後續討論狀態呈現。

【需實測或決策】畫稿刻意不模擬完整每日資料、任意自然語言指令解析或所有刪除相依關係；匯入核對、分享附件與邀請僅展示入口／版型。後續先根據使用者對資訊層級與流程的回饋修稿，再補齊細部狀態。此輪 UI 檢查不等於 App 功能或真機驗收。

## 第一輪回饋修訂

【已確認規格】已依四點回饋補至 22 個畫面（詳見新版 spec §10）：用品手動新增／編輯、行程範圍內找不到商品、站點內問 AI，以及店名／地址複製。

【已確認規格】本輪檢查：新增共同用品「雨傘」後清單可見；切到私人用品可編輯名稱與數量；商品 B 保留待買後不新增弘大行程；站點廁所提問沿用該站名稱、區域及日期。窄螢幕內容寬度與可用寬度均為 313 像素，未見水平溢出。

【需實測或決策】複製按鈕嘗試寫入剪貼簿，預覽環境若不提供權限則顯示可手動選取文字，不假報成功；真 App 複製與 AI 查詢需於開發後真機驗收。其他使用者行程目前只呈現可讀取的旅伴共同行程，公開陌生人行程另待釐清。

## 餐廳問答推薦卡修訂

【已確認規格】新增 W05：餐飲問答呈現介紹、從本站出發的路程、附平台／尺度／評論數／查詢時間的評分，並呈現資料未知的替代狀態。

【已確認規格】已檢查甜點問題可切到推薦卡，窄螢幕寬度 313 像素無水平溢出。畫稿中的店家、路程與評分均明示虛構示意；沒有進行實際搜尋，不代表來源取得或 AI 準確度已驗收。

## 雙 AI 模式修訂

【已確認規格】增加第 23 個畫面「AI 模式與額度」，支援本機 GPT 訂閱與由產品擁有者統一提供給旅伴的 Claude API 額度。模式標示常駐於精簡入口，啟用 Claude 時明示 API 額度。

【已確認規格】本輪線框檢查：切到 Claude 並選處理中，可看到正在使用共用 API 額度；工作執行中切換新工作預設模式，舊工作仍標記原模式；本機不可用時，本站問答保留等待，沒有自動切 Claude。沒有實際 API 呼叫、費用、設定變更或部署。

【需實測或決策】API 用量回報、共用帳號授權、限額與預算、搜尋能力、後端憑證保存及正式工作去重，待開發規劃與真實環境驗證。
