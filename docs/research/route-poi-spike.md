### 首爾大眾運輸的錯誤內容

每一筆都是同一個錯誤：

```
MKErrorDomain code 4（MKError.directionsNotFound）
MKErrorGEOError = -8, NSDebugDescription = "FAILED_NO_RESULT"
localizedDescription = "Directions are not available."
```

**重點**：這和「真的沒有路」（例如 H24 渡輪）是**同一個錯誤碼**，App 無法從錯誤判斷「此地區不支援」還是「這兩點之間沒有路線」。

建議（實作 WP4 時）：
- 韓國地點 + 大眾運輸：**不呼叫 Apple**，直接回 `ROUTE_UNAVAILABLE`（reason = `notSupportedInRegion`），並顯示外開 Naver／Kakao 按鈕。省一次請求，也讓 UI 文案能講清楚原因。
- 其他情況收到 `MKError.directionsNotFound`：回 `unavailable`（reason = `unknown`，文案「無法估算這段路線」），不猜分鐘數。

## 2. 誤差【需手動參考值】

`route-results.csv` 已有 Apple 分鐘數；需在同一時段查 Naver Map／Kakao Map（首爾）、Google Maps／ジョルダン（廣島）填參考值後，才能算中位數與 P90 誤差。

**先看到的疑點（需參考值確認）**：首爾市區開車時間明顯偏樂觀。13 組平均時速超過 40 km/h，例如：

| OD | 距離 | Apple 開車 | 換算時速 |
|---|---|---|---|
| S19 서울역 → 홍대입구역 | 5.7 km | 5.5 分 | 63 km/h |
| S20 명동역 → 성수역 | 7.4 km | 7.7 分 | 58 km/h |
| S13 성수역 → 건대입구역 | 1.5 km | 1.6 分 | 57 km/h |

首爾市中心平日白天實際車速通常遠低於此，推測 Apple 在韓國沒有即時路況，接近自由車流。若參考值證實，首爾開車也可能不過門檻（中位數誤差 ≤ 20%）。

## 3. POI 搜尋【已實測】

判定「找到正確地點」= 第一筆就是預期的店（連鎖店需是指定分店）。

| 城市 | 第一筆正確 | 有結果但不對 | 無結果 |
|---|---|---|---|
| 首爾（15） | 8 | 3 | 4 |
| 廣島（15） | 10 | 5 | 0 |

**首爾**
- 無結果（全是 `MKErrorDomain 4 / -8`）：`올리브영 명동타운`、`オリーブヤング 明洞タウン`、`무신사 스탠다드 성수`、`Musinsa Standard Seongsu`。韓國連鎖品牌的新分店覆蓋不足。
- 不對：`Olive Young Myeongdong Town` 回傳「명동」這個區域；`Olive Young 明洞` 回傳梨泰院分店；`다이소 명동역점` 只回名稱「다이소」，看不出是哪家分店。
- 正確：광장시장（韓／英／簡中都找到）、명동교자（韓／繁中）、어니언 성수（韓／英）、스타벅스 명동（兩家分店可區分）。
- 地址：韓國地點回傳韓文地址，但常缺門牌號（例如「서울특별시 명동 명동길」）。

**廣島**
- 景點與單店全部找到（お好み村、原爆ドーム、ドン・キホーテ 八丁堀、にしき堂本店）。
- 連鎖店查詢（`UNIQLO Hiroshima`、`優衣庫 廣島`、`Don Quijote Hiroshima`）第一筆是 5–6 km 外的郊區分店；日文查詢反而較準。**不能直接取第一筆**，需列候選讓使用者選（符合規格「地點不確定時列候選」）。
- `広島城` 第一筆是「二の丸跡」，`Hiroshima Castle` 是「三の丸」：同一景點內的子地點，需在候選中顯示。
- 地址完整（含郵遞區號與門牌）。

**名稱語系**：`MKMapItem.name` 依**裝置語系**回傳，不依查詢語言。系統語系 zh-Hant 時，광장시장 回「廣藏市場」、原爆ドーム 回「原子弹爆炸圆顶屋」（簡體）；改成 ko 語系後回「광장시장」「원폭돔」。
- 影響外開 Naver／Kakao：要帶韓文店名，不能直接用 `mapItem.name`。建議 Place 同時存「顯示名稱」與「在地名稱」；在地名稱可在服務端以 Apple Maps Server API 指定 `lang=ko` 取得（待驗證），或使用者確認時保留分享來源的原文。
