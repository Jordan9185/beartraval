# BeaRTravel：懶人收集與 AI 整理產品主軸

版本：v1.0 · 2026-09-27

【已確認規格】產品負責人於本次主軸討論確認「懶人整理與 AI 辨識都是重點」，並同意依此重新調整。本文件是現行產品定位、核心流程與新增驗收基準；規格採用不等於功能已完成或已驗收。

## 1. 核心價值

**把旅行資料丟進來，AI 幫你看懂、整理、提出安排；你只需要確認重要選擇，就能帶著行程出發。**

【已確認規格】三個核心為：**懶人收集、AI 辨識整理、可直接使用的旅程**。AI 辨識與整理是主流程，不是最後才補的助手功能。聊天助手是其中一個入口，不能以「有聊天功能」代表 AI 整理已完成。

使用者提供內容、選偏好並確認重要決定；App 負責讀取、辨識、分類、保留來源、補查與提出建議。成功的判斷是辨識正確、減少操作、結果能直接用於旅行。

## 2. 一條完整主線

【已確認規格】

```text
分享／貼文字／連結／選照片
  → 先保存，不必選類型或先建立旅程
  → AI 辨識地點、商品、行程或混合內容
  → 自動整理個人清單／草稿，集中顯示少數待確認項
  → 建議旅程與日期，使用者核對並確認
  → 正式旅程，可修改、撤回、重新安排
  → 今天／地圖／導航／司機卡／完成購買
```

### A. 先收好

- 分享面板不要求先分類、選 Trip、抄店名或等待路線。主 App 也提供不依賴既有 Trip 的收件入口。
- 保存實際取得的文字、連結、圖片與順序；只收到連結就照實保存連結。只有來源真的保存成功才顯示成功。
- 未登入／離線先保存在裝置；登入後確認未歸屬內容的帳號，再同步。帳號隔離不因追求少操作而省略。
- 狀態要區分已保存在裝置、待同步、AI 整理中、已整理、部分待確認、資訊不足與失敗；失敗保留已完成部分。

### B. AI 看懂並整理

| 內容 | 整理結果 | 必須避免 |
|---|---|---|
| 地點／餐廳 | 原文店名、當地名稱、地區、分店候選、地址線索、類別與來源 | 把貼文標題、料理名、搜尋框或手機時間當店名 |
| 商品 | 多件商品、品牌／品名、可取得的型號、店家線索與來源 | 把品牌當分店、把門市存在當成有售／有庫存 |
| 既有行程 | 每天的站點、明示日期、順序、時間、交通與疑似固定事項 | 重排使用者指定的日期與地點、替未知時間補數字 |
| 混合貼文／圖片 | 分開的地點、商品及可編輯行程草稿，保留彼此來源關係 | 強迫整篇只能是一種類型、只保留第一個辨識項目 |

- 明確的內容自動進個人清單或草稿；模糊分店、商品身份與作者意圖集中待確認。自動歸檔可更正／撤銷。
- 來源明示、外部查得、AI 建議與未知要能區分。補查不得覆蓋使用者更正。
- 展示「辨識到什麼、存到哪裡、哪些待確認、下一步能做什麼」；原始 OCR 與詳細依據收在次要區域。
- 地址文字與地圖定位是不同狀態；有地址不代表已取得可信座標。

### C. 幫忙組成旅行

| 使用者起點 | App 行為 |
|---|---|
| 已排好的行程 | 按原文整理，保留指定日期與 Fixed 候選，讓使用者核對 |
| 部分行程 | 保留已有日期、順序與固定事項，為尚未提供安排的日期補可確認的建議；明確要求自由活動／留白時保留 |
| 一堆收藏與想買商品 | 依選定旅程的地區、日期、已安排站點與可得路線，提出日期／店家建議 |
| 「東京五天」與想去清單 | 提出有來源、可修改的草稿；使用者指定地點與日期必須保留 |
| 空白旅程 | 可以手動加入，也可稍後加入 AI 整理結果；沒有假 Base Route |

【已確認規格，2026-09-27 再次澄清】完整行程、部分行程及一句話需求都是建立行程的正常輸入。旅程名稱、表單日期與原始提示須一起理解；名稱已寫目的地時，不要求使用者在提示再寫一次。原文與補充背景分開保存，AI 新增建議與原有安排分開標示。

- 個人地點與商品能直接「加入旅程」，接著選 Trip／日期；不要求先學會「發布到旅伴清單」才能排程。
- 只有一趟可編輯旅程時可預選，多趟顯示目標；確認前清楚說明哪些選定項目將讓旅伴看見。私人收件原文不整份自動公開。
- 建議顯示理由、日期、定位狀態、可取得的增加時間及 Fixed 風險；路線未知仍可由使用者確認排程，不宣稱最順路。
- 未定位項目可建立帶名稱、地址線索與來源的待定位 Stop。歧義分店不能被 AI 自選為已確認 Place。
- 只有明確確認才改正式行程；過期版本需重新載入、重看與確認。

### D. 旅行途中能用，也能改

- 已定位／待定位站點都要能人工修改日期、時間、停留、順序、地點及移除；保留來源與收藏／商品關聯。
- Fixed 不得由 AI 自動移動；使用者本人明確修改 Fixed 時，顯示影響再確認。
- 商品能更正、移除、取消安排、換店、改日、勾選購買及撤銷；安排購買不等於有貨。
- 今天可直接處理當日安排與待買事項；導航與司機卡沿用已核對的名稱和當地地址。
- 改錯能回頭、失敗能重試、重送不重複。不能用刪除整趟旅程作為修正單一站點的退路。

## 3. 五個分頁的責任

【已確認規格】維持旅程／今天／地圖／收藏／購物五個分頁。

| 分頁 | 核心責任 |
|---|---|
| 旅程 | 建立旅行、取得 AI 草稿、確認及編輯每日安排 |
| 今天 | 執行選定日期的行程、查看下一站、完成購買 |
| 地圖 | 對應選定日期的地點分布、順序與導航；未知地點不畫假圖釘 |
| 收藏 | 個人／共同地點、辨識狀態、待確認項、排入旅程或查看已排日期 |
| 購物 | 個人／共同商品、候選店與來源、安排及購買紀錄 |

【已確認規格】各頁共享目前 Trip；今天與地圖共享選定 Day。新建、加入、刪除 Trip、權限變更及回前景後資料要收斂。個人清單不因切 Trip 消失，與選定 Trip 的共同資料明確區分。

【建議】收件匣集中呈現處理歷史及例外；成功結果直接出現在收藏／購物／草稿，不必每次打開收件匣。入口位置與一次呈現的結果數以真機可用性測試調整，未指定新的分頁或視覺樣式。

## 4. 自動化與確認邊界

【已確認規格】

| 動作 | 預設 |
|---|---|
| 保存來源、辨識、分類、查證、提出去重結果 | 自動；錯誤不得造成來源消失 |
| 明確項目進個人清單、產生行程草稿 | 自動、可更正／撤銷，不修改正式 Trip |
| 選擇歧義分店、轉入共同清單、套用／修改正式行程、標記購買 | 使用者明確執行；可合併在清楚的確認步驟中 |
| 算不出路線或無法判斷 Fixed 可行性 | 顯示未知；未定位 Fixed 仍保留時間約束 |
| 查店失敗或沒有庫存證據 | 保存商品仍成功；補查可重試，庫存未知 |

`CLAUDE.md` 的權限、revision、來源、Fixed 與未知值規則持續適用。懶人操作不得以默默公開私人內容、猜測分店或假造分鐘數達成。

## 5. 新增驗收基準

【已確認規格】以下是目標情境，全部尚待逐項取得本版證據。舊 AC-01～14 保留 ID，按本文件更新後的流程解讀。

| ID | 情境與應見結果 |
|---|---|
| AIJ-01 | 沒有 Trip，分享純圖片／文字／URL；不用分類或建 Trip 就保存，主 App 找得到狀態與來源 |
| AIJ-02 | 多店、多商品與混合樣本能分項；不把手機介面文字當內容；每項可回查來源 |
| AIJ-03 | 明確項目自動進個人清單，歧義集中待確認；更正／撤銷後重跑不覆蓋人工決定 |
| AIJ-04 | 辨識、補查或上傳中斷，來源保留；核心保存成功但查店失敗時不報整筆加入失敗 |
| AIJ-05 | 個人地點／商品直接選 Trip／日期加入；共同可見範圍清楚，重開／重送／兩裝置操作不重複 |
| AIJ-06 | 已有行程、收藏集合及短句三種起點皆能產生可核對的安排；指定日期與地點不遺失，套用前不改正式旅程 |
| AIJ-07 | 空白日、未知路線、未定位 Fixed 不顯示假 0 分或錯稱沒有固定事項；確認內容與提交一致 |
| AIJ-08 | 排入後可改日、時間、順序、地點、移除及重排；商品可改名、移除、取消安排、換店 |
| AIJ-09 | 新建／切換／刪除 Trip、切 Day、回應逆序與重新開 App，五頁資料及今天／地圖日期一致 |
| AIJ-10 | 從當日安排導航、出示當地地址、勾選／撤銷購買；來源與選店不因跨頁消失，旅伴看見更新 |
| AIJ-11 | 離線重送、被撤權、版本過期、返回／下滑取消均有明確結果，沒有靜默遺失或殘留待確認操作 |
| AIJ-12 | 問 AI 時能取得相同的已選店家、地址線索與定位狀態；資料不足明說，回答不代替正式提交 |

【建議】每份真實樣本記錄：辨識正確／漏項／錯項、正確自動歸檔數、人工更正數、必填欄位數、操作步數、保存到結果可見時間，以及排程後各頁一致性。與調整前同一樣本比較，驗證是否真正省事。

【需實測或決策】準確率、完成率、延遲與費用的數值目標，先建立可回溯樣本及基線再定；不得先宣稱百分比、固定秒數或省下多少步。假資料測試不能取代真 AI 與裝置流程證據。
