# 旅遊行李清單：功能提案

日期：2026-09-28 · 版本：v0.1 · 狀態：規劃草稿，尚未採用、開發或驗收。

【已確認規格】本次使用者提出「旅遊帶東西的清單，規劃一下」。本次交付為規劃，不代表授權實作或雲端部署。

【建議】功能名稱用「行李清單」，解決三件事：知道要帶什麼、知道哪些還沒裝好、知道共同物品由誰帶。先以「每人私人清單＋旅伴共同物品」規劃；使用方式尚待產品負責人確認。

## 1. 產品定位與既有規則

- 【已確認規格】遵循 [CLAUDE.md](../../CLAUDE.md)、[現行產品主軸](ai-first-product-direction.md)及[主線交付計畫 v3](../planning/ai-first-delivery-plan-v3.md)：減少整理負擔，維持旅程／今天／地圖／收藏／購物五個分頁，正式行程仍須使用者確認才變更。
- 【建議】行李屬於旅程的出發準備，放在每趟旅程內；與「想在旅行中購買的商品」分開。買到物品不代表已裝進行李。
- 【建議】一趟旅程各有一份本人清單與一份共同物品清單；私人內容預設只有本人可見，包括項目、備註及完成數。
- 【建議】不要求先填目的地、天數、同行人或行李種類才能開始。沿用目前旅程；先給基本範本，允許直接新增。
- 【需實測或決策】本提案是新增支線，不自動重排 AJ-0～AJ-4 的交付優先順序；正式排程需另確認。

## 2. 使用者流程與入口

【建議】主要流程：

```text
旅程 → 選一趟旅行 → 行李清單
  → 套用基本清單／直接新增／沿用上一趟
  → 補上自己的物品，必要時新增共同物品並指定攜帶者
  → 打包時逐項勾「已裝好」
  → 出發前只看「還沒裝好」與「出發當天再拿」
```

| 位置 | 建議呈現 | 標記 |
|---|---|---|
| 旅程詳情，每日行程上方 | 「行李清單」入口，顯示「我的已裝好 8／12 項」；共同進度另列 | 【建議】 |
| 今天，旅程摘要旁 | 精簡的「行李清單」捷徑；未建立時不顯示假進度 | 【建議】 |
| 行李清單頁 | 「我的物品／共同物品」切換、分類清單、未完成篩選、頁面主動作「新增物品」 | 【建議】 |
| 初次空白頁 | 主按鈕「使用基本清單」；次要文字動作「自行新增」「沿用上一趟」 | 【建議】 |

【建議】沒有旅程時，不為了開此頁偷偷建立 Trip。先從既有建立旅程流程開始；無 Trip 的獨立行李清單不列入第一版。既有旅行資料收件功能仍可不依賴 Trip 使用。

【建議】清單範例，僅為畫面內容示意：

```text
首爾七天 · 行李清單
我的物品 | 共同物品
已裝好 2／4 項             只看未完成

證件與支付
已裝好  護照 × 1
未裝好  錢包 × 1           出發當天再拿

電子用品
已裝好  充電線 × 1
未裝好  行動電源 × 1

新增物品
```

【已確認規格】實際 UI 使用系統字級與 SF Symbols，沿用熊毛棕主色；每頁一個主色按鈕、每列最多兩個標籤。新增頁採一般導覽，避免將 sheet 掛在 List 的 Section 上。

## 3. 第一階段：可直接拿來打包

以下功能均為【建議】，尚未實作。

| 功能 | 第一版行為 |
|---|---|
| 快速開始 | 基本範本分為證件與支付、衣物、盥洗保養、電子用品、個人用品、其他；套用後都是可改可刪的普通項目 |
| 範本選擇 | 提供「一般旅行」「海外旅行」等選項；不根據地點猜使用者國籍、需求或一定需要護照 |
| 新增與編輯 | 名稱必填；數量預設 1、分類預設其他；備註與「出發當天再拿」選填，不強制填完多個欄位 |
| 一次新增多項 | 可貼多行文字，一行一項；先確認辨識出的行，再批次加入。第一版不依賴 AI，不能把貼上成功說成已理解所有內容 |
| 打包狀態 | 僅「未裝好／已裝好」，可隨時取消勾選。數量 5 代表需準備 5 件，整項勾選表示該項所需數量都已裝好 |
| 尚未採買 | 可用備註記「待買」；第一版不新增第三套購物流程，也不自動建立 Shopping 商品 |
| 減少找尋 | 按分類顯示、只看未完成、已完成收合；另可篩選「出發當天再拿」 |
| 完成進度 | 以項目數計算，例如 8／12 項；數量不當分母，已刪除項目不計入。空清單顯示「尚未加入物品」而非 100% |
| 沿用上一趟 | 由本人選一趟仍有權讀取的旅程，複製自己的名稱、分類、數量、備註及當天標記；新項目全部未裝好，不帶共同分工與他人的內容 |
| 共同物品 | 顯示「誰帶」與已裝好狀態；可暫不指定，顯示「尚未分工」。不把私人項目自動公開 |
| 離線 | 已載入的清單可離線查看、新增、編輯、刪除、勾選／取消；保存到裝置後顯示待同步，重開 App 仍保留 |

【建議】基本範本直接隨 App 提供，套用不需等 AI 或 Mac 上線。重按同一次套用不重複新增；再次套用只補尚未套用的範本項目，不覆蓋人工更正，不補回使用者已刪除的項目。重複名稱只提醒，不擅自合併，例如兩條不同充電線可各自存在。

【建議】物品數量增加或名稱改變時，已裝好的項目改回未裝好並明示；只改分類、備註、減少數量或取消當天標記則保留狀態。改共同攜帶者也重設為未裝好，避免把原攜帶者的完成狀態誤算給新的人。

【建議】刪除提供撤銷；離線新增後又刪除的同一項不應在重連後重新出現。第一版不提供一次重設整趟打包狀態；下一趟用複製即可。

## 4. 個人與共同物品的權限

以下是【建議】的新功能權限，不代表既有 Trip 權限已經變更。

| 操作 | 擁有者／可編輯成員 | 僅檢視成員 | 非有效成員 |
|---|---|---|---|
| 查看／管理自己的私人清單 | 可以 | 可以；限本人私人資料 | 不可以 |
| 查看他人的私人清單、備註、完成數 | 不可以 | 不可以 | 不可以 |
| 查看共同物品 | 可以 | 可以 | 不可以 |
| 新增、修改、刪除、勾選共同物品 | 可以；記錄操作人 | 不可以 | 不可以 |
| 指定共同攜帶者 | 僅能指定有效的擁有者／可編輯成員 | 不可以 | 不可以 |

- 【建議】「誰帶」是分工資訊，不把共同項目變成只有指定者可編輯。明確顯示由誰完成，避免全員都以為是自己裝的。
- 【建議】第一版建立時明確選「我的物品」或「共同物品」，共同新增畫面提示「這趟旅程的旅伴都看得到」。不提供隱晦的自動公開或自動搬移。
- 【建議】未分工的共同項目不可勾為已裝好；由可編輯成員先選「我來帶」或指定攜帶者，再勾選。
- 【建議】攜帶者退出、被移除或改成僅檢視：共同項目保留、分工清空、改為未裝好，顯示需重新分工；私人資料仍不轉給旅程擁有者。
- 【建議】刪除 Trip 時連同清單刪除；退出／遭撤權時裝置移除該 Trip 快取及待送操作。離線裝置須在下次連線得知撤權後清除，不宣稱可即時遠端清除離線快取。
- 【需實測或決策】僅檢視成員是否需要承擔共同物品？本版先維持共同內容唯讀；若要開放，只新增明確受限的打包權限，不擴大其正式行程權限。

## 5. 第二階段：AI 與旅行情境

以下均為【建議】，不列入第一版必要條件。

| 功能 | 行為與限制 |
|---|---|
| AI 補充建議 | 讀取使用者可見的旅程日期、目的地線索與活動，提出缺少物品及簡短理由；地點、活動或天數不足時明說，不要求必填長問卷 |
| 一鍵加入建議 | 顯示建議清單供勾選，一次加入；AI 不修改已勾狀態、不移除人工物品、不替旅伴分工 |
| 認得個人習慣 | 明確選擇保存為私人範本；不因曾帶過藥品等內容就推測或公開個人情況 |
| 出發前提醒 | 使用者自行設定時間，先做本機通知；時區、日期改動及通知權限不足要有明確結果 |
| 購物連動 | 從行李項目明確選「加入待買」；保留對應關係。已購買只表示買到，仍需本人勾已裝好 |
| 回程檢查 | 另開回程檢查輪次，保留去程打包紀錄；不直接重設原清單 |

【已確認規格】若接 AI，沿用個人 ChatGPT／Codex 工作佇列；Mac 離線或額度不足時等待，不退回付費 API。現有五個正式入口尚不包含行李建議，新增工作種類、契約與測試需另外實作。

【建議】AI 只送出該次建議必要且有權限的資料，不附上其他旅伴私人清單。一般物品建議不能冒稱天氣預報、航空攜帶規定或入境要求；這些資訊只有取得可核對來源與時間才顯示，沒有時提供一般建議即可。

## 6. 工程設計與現況落點

【已確認規格】本次本機檢視基準為 `0e7f3ba`。在 App 模組、後端及既有產品規格搜尋，尚未找到行李清單功能；本次沒有重驗雲端或裝置。

| 已檢視的位置 | 現況及本提案影響 | 標記 |
|---|---|---|
| `Features/RootView.swift` | 已有五個分頁；新頁由旅程／今天進入 | 現況【已確認規格】；新入口【建議】 |
| `Features/TripViews.swift` | 旅程詳情目前主要列每日安排，可在上方加入口 | 現況【已確認規格】；新增列【建議】 |
| `Features/TripStore.swift` | 已有 Trip 切換、快取及過期回應保護；清單也需按帳號與 Trip 載入 | 現況【已確認規格】；延伸【建議】 |
| `AppCore/OfflineQueue.swift` | 目前只有收藏、想去及購買操作，沒有行李操作；佇列解碼及本機寫檔失敗的處理要一併納入 | 現況【已確認規格】；延伸【建議】 |
| `Features/SessionModel.swift` | 目前 flush 呼叫未呈現 rejected 結果；行李同步需顯示遭拒／衝突，不能靜默消失 | 現況【已確認規格】；修正【建議】 |
| `AppCore/Sharing.swift`、`supabase/README.md` | 既有角色、RPC、Realtime 事件可作共同物品基礎；私人事件需隔離 | 現況【已確認規格】；延伸【建議】 |

【建議】新增獨立 `PackingItem`、`PackingRepository`、`PackingStore`、`PackingListView` 與 `PackingItemRow`，不把行李塞進 Shopping 或 Stop。以下是待定設計名稱，尚無對應表／RPC：

| 資料 | 最小契約 |
|---|---|
| 物品身份 | `id`、`trip_id`、`scope`（私人／共同）、私人 `owner_user_id`、`created_by`；服務端限制兩種範圍的合法欄位組合 |
| 物品內容 | 名稱、分類、正整數數量、備註、當天再拿、共同攜帶者；必要長度限制 |
| 打包狀態 | `packed`、`packed_by`、`packed_at`；不是購買狀態，也不寫入正式行程 |
| 更新保護 | `revision`、`updated_at`、`deleted_at`；新增使用客戶端穩定 UUID，重送保留同一操作識別碼 |
| 範本來源 | 範本版本與項目鍵、複製來源及操作識別碼；用於追蹤來源、同次重送去重及保留已移除決定 |

【建議】寫入一律由 RPC 驗證帳號、有效成員、scope、角色、攜帶者及項目版本；不能只依 UI 隱藏按鈕。私人資料僅本人可讀寫，旅程擁有者沒有私人內容特權。

【建議】同步契約：

1. 打包送出明確目標狀態（已裝好／未裝好），不用「切換」指令，避免重送翻回原狀。
2. 每筆更新帶預期版本與操作 ID；同筆並發不靜默覆蓋，不同物品互不阻塞。版本衝突保留本機意圖，顯示最新內容供重新套用。
3. 同裝置離線連續修改需按項目合併或在前一筆成功後銜接新版本；不可讓第二次正常勾選因沿用舊版本而誤報衝突。
4. 本機待送資料先可靠寫入再回報保存成功；寫檔失敗保留輸入並顯示錯誤。暫時網路錯誤重試，權限／刪除拒絕停止重試且呈現結果。
5. 私人清單使用本人可讀的變更通知／重新載入，不能將私人名稱、數量、備註或完成數放進全 Trip 的事件或共用快照。
6. 共同清單可沿用 Trip 事件通知後重新讀取；打包不改 `route_revision`、Stop 或既有 proposal，不觸發路線重算。
7. 登出或換帳號時取消舊帳號進行中的請求，隔離並清除本機快取與佇列；新增操作種類不得讓舊格式整份佇列解碼失敗而遺失。
8. 所有載入與回覆同時核對帳號、Trip 及請求世代，晚到的 A 旅程回應不可顯示於 B 旅程。

【已確認規格】新增 migration 須向後相容；修改既有 RPC 時新參數有預設值，處理舊簽名與 grants。部署先說明影響並 dry-run。本次僅規劃，不建立 migration。

## 7. 工作拆分與交付門檻

以下工作包與順序均為【建議】，不是排程承諾。

| 工作包 | 可驗證成果 | 依賴 |
|---|---|---|
| PK-01 資料與權限 | 私人／共同資料、CRUD、版本與去重、離開／刪除策略，直接呼叫後端也不能越權 | 確認第一版使用方式與權限 |
| PK-02 打包主流程 | 旅程入口、基本範本、增改刪、數量、勾選、未完成篩選、沿用上一趟 | PK-01 |
| PK-03 共用與同步 | 分工、今天捷徑、進度、離線持久化、重連與兩裝置衝突、同步拒絕提示 | PK-01、PK-02 |
| PK-04 真機驗收 | 完整出發打包流程、Release 清單穩定性、換旅程／換帳號與可讀性 | PK-01～03 |
| 後續 AI／提醒／購物 | 另定契約與樣本驗收，不和第一版混報完成 | 第一版驗收及優先順序確認 |

【建議】第一版交付必須包含 PK-01～04；僅做出打勾畫面不足以稱為可旅行使用。改 AppCore／Features／ShareCore 後跑套件測試；對新 RPC 跑 SQL 權限、重送及並發測試，再做模擬器與 Release 真機流程。沿用專案簡單非泛型清單列，避免 Release 堆疊問題。

【需實測或決策】先完成資料契約與離線改動評估，再估工期；現階段不承諾「一天完成」。程式、部署、安裝、實測、使用者驗收分開記錄。

## 8. 第一版驗收情境

以下均為【建議】的待驗收標準，目前沒有完成證據。

| ID | 情境與預期結果 |
|---|---|
| PK-AC-01 | 從指定旅程開清單並套用範本，不重填旅程資訊；不新增 Stop 或修改正式行程 |
| PK-AC-02 | 新增、批次新增、編輯、刪除及撤銷可用；失敗保留輸入，數量只接受正整數 |
| PK-AC-03 | 勾選／取消立即更新本人畫面，關閉再開仍存在；完成數按項目計，空清單不是 100% |
| PK-AC-04 | 複製上一趟只帶本人可讀的物品內容，完成狀態全清空；重送不重複，重套範本不復活已刪項目 |
| PK-AC-05 | 兩帳號同 Trip：看不到彼此私人內容與完成數；擁有者也無法經 API 讀取他人私人清單 |
| PK-AC-06 | 共同分工與勾選在兩裝置收斂；未分工不能裝好；指定者離開／降權後需重新分工及打包 |
| PK-AC-07 | 僅檢視者能管理本人私人清單，不能經 UI 或直接 API 寫共同物品與正式行程 |
| PK-AC-08 | 先載入後斷線，增改刪及連續勾選後強制關閉再開，內容與待送狀態保留；重連收斂且無重複 |
| PK-AC-09 | 兩裝置同改一項會明示衝突；同步被撤權、Trip／物品已刪、寫檔失敗均有結果，不無限重送或假成功 |
| PK-AC-10 | 快速切 Trip、回應逆序、回前景、登出換帳號後，清單與進度不串到另一趟或另一人 |
| PK-AC-11 | 增加數量、改名或換攜帶者後正確回到未裝好；調分類或備註不破壞既有完成狀態 |
| PK-AC-12 | 真機 Release 跑完整打包流程，大字級、長物品名、長清單仍可讀可點且不閃退；Mac 不在線仍可手動打包 |
